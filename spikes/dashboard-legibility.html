Which number comes first? A legibility spike for the repository detail page

Three invented histories are shown side by side: a series that climbs, a series that holds still, and a series that falls away across the same fourteen days. Each panel is drawn twice, once per acquisition metric and once per interest metric, and each panel carries the same values as a table, so nothing here exists only as a picture. The point of the page is to let a person choose the order the sections appear in on the real page.

The words spiking, flat and decaying in the panel labels are vocabulary for this review only. They name the shape of invented data so the three cases can be told apart. They are not claims about any repository and the dashboard would never show them.

How to use this page, and what it asks you to decide

Open the three panels and compare them. Then record the answers below in docs/reviews/dashboard-legibility-spike.json. No agent writes that file; a person does, and no task of mine may claim it passed.

  1. Which number should a maintainer see first on the repository detail page?
  2. Does the small-repository panel need a treatment of its own, or is the same layout legible enough at those values?
  3. Does unique cloners earn its own chart, or does it stay a headline number beside the clones chart?
  4. Should the falling-away case be charted at all, or should the page state it as data it cannot read?
  5. Is this page kept as decision evidence, or deleted once the decision is recorded?

Every panel states a window of 2026-03-01 to 2026-03-14, and every panel contains one day with no stored observation. That is deliberate: the order you pick has to be legible while a day is missing, not only when the archive is complete.

How this page is wired: not at all. It is one file under spikes/. No module under src/ imports it, no command serves it, and the repository configuration does not list it. The real chart is written independently in src/views/components/line-chart.js by a later task, and it reads the archive rather than a hand-typed table. The shapes, colours and wording here are proposals to be decided, not a description of shipped behaviour.

Accessibility of this page, for the reviewer's own judgement: one language declaration, one title, one main landmark, a skip link as the first focusable element, a heading sequence that skips no level, a table beside every chart, gap days named in text, and no state carried by colour, icon or badge. It has no script, no inline handler, no remote font, no remote image and no motion.
